Connect Live Data

Out of the box this app runs entirely offline: recipes come from its own knowledge base and images are drawn rather than photographed. Add a key below to switch on real YouTube results and real photography.

Currently using

This page must be served over http, not opened as a file. Run python3 -m http.server 8080 in the project folder and visit http://localhost:8080/setup.html. Browsers block API calls from file:// pages, and a published Artifact page blocks them too.

How it works

  1. 1 Get a free key

    Each card below tells you exactly where to get one and what the free tier allows. YouTube and Pexels are the two that matter most.

  2. 2 Test it here

    Paste it in and press Test. This fires the exact request the app makes and shows you the real response, so a bad key fails with a reason instead of silently.

  3. 3 Make it permanent

    Keys typed here live in this browser only. To ship it, put them in assets/js/core/config.js and switch the matching providers.* entry.

The config to end up with

In assets/js/core/config.js:

providers: {
  ai:              'local',      // or 'openai' | 'gemini' | 'claude' | 'proxy'
  video:           'youtube',    // real YouTube search results
  photo:           'pexels',     // real photography ('youtube' works with no extra key)
  ingredientPhoto: 'wikimedia',  // keyless ingredient photos
  recipe:          'local',      // or 'spoonacular' | 'edamam'
},

keys: {
  youtube: 'AIza...',
  pexels:  '...',
},
About putting keys in front-end code. Anything in config.js is visible to every visitor. That is fine for a YouTube key you have restricted to your own domain (Google Cloud Console → Credentials → Application restrictions → HTTP referrers), and fine for a personal or local project. For anything public and billable, point endpoints.ai / endpoints.video at a small server of your own that holds the secrets, and set the matching provider to proxy.
